## Acceptance checks

1. Authorize tenant/facility and reject held charges before allocation
2. Read versioned charge/tax/payer inputs and recheck versions under G-LATE policy
3. Number, immutable snapshot, participant effects, audit and outbox share the accepted G-COMMIT transaction
4. Repeated request cannot duplicate bill, number or financial effects
5. Original amounts/taxes/lines remain immutable through every application path
6. Patient plus payer shares equal bill total exactly
7. Authorize within the action, including direct invocation
8. Rollback leaves no partial financial effects or consumed number
9. Identical operation retry returns its prior result; changed payload conflicts

## Required contract context

**C-01**

Core context: {tenant_id, facility_id, actor_id, operation_id, source_address}; constructed from authenticated membership, never trusted from request JSON. Permissions are checked inside each action. Money is integer paise; percentages use exact rational arithmetic and an explicit rounding policy. Transaction runner supplies same-database unit-of-work, audit append and outbox append. Audit includes actor/tenant/facility/record/action/before/after/time/source address; no application update/delete path. Outbox row: {event_id, type, version, tenant_id, aggregate_id, payload, occurred_at}; it is committed with business state, then delivered with a consumer inbox key. API/web/provider/route fragments have one bootstrap registration convention. DeliveryPort returns accepted/rejected/outcome_unknown plus provider reference; unknown is reconciled before resend. No package is assumed active merely from this definition.

**C-02**

EncounterBillingSnapshot(context, encounter_id, expected_revision) returns patient/recipient data, facility/GSTIN/state/year, financial class, posted and reversed charge references, outstanding exception count, approved discount references, package/entitlement inputs and charge_set_revision. Every charged line includes stable id, service date/class, quantity and exact posted amount. Missing tenant/facility/encounter => NotFound; changed revision => StaleInputs. TaxSchedule(service,date,policy_version) returns classification/rate/effective interval. PayerTerms(payer_ids,date,versions) returns share, exclusions, caps and package rules. DepositBalance and DoctorFeeRules return versioned, scoped inputs. All authoritative reads participate in the same snapshot/version-check policy; absent policies never imply zero tax or full payer coverage. Real provider adapters require upstream store bindings G-UPSTREAM.

**C-03**

FinaliseBill(context, encounter_id, expected_charge_revision, operation_key) returns bill_id, number, immutable content_version, document_type, patient_paise, payer_shares_paise, rounding_paise and completion status. It owns no charge/pricing policy mutations. Guard failures: NotFound, Forbidden, TenantSuspended, HeldCharges, StaleInputs, MissingRecipientDetails, PendingDiscountApproval, MissingPolicy, AlreadyFinalised/IdempotencyConflict as settled by G-LATE. No number allocated until all preconditions pass; series is keyed by tenant+GSTIN+financial_year+document_type and updated transactionally, never via a nontransactional sequence. Amounts, number, financial applications, audit and outbox commit atomically subject to G-COMMIT. BillFinalised.v1 contains event_id, tenant/facility, bill_id, content_version, immutable snapshot reference and operation_id; no duplicate physical bill on retry. Finalized amount snapshot is immutable; enrichment with external IRN/status requires separate delivery metadata and G-DOCUMENT. Lock all required same-database resources in a documented global order; provider versions must still match before commit.

**C-04**

Financial participant interfaces accept FinalizedBillSnapshot plus transaction context and stable operation id. ApplyDeposits returns ordered allocations and refundable remainder; OpenReceivables creates patient/payer balances with deposit reductions and no double reduction; PostLedger emits balanced immutable bill/deposit entries. They are called synchronously under the proposed G-COMMIT boundary, and do not each begin independent commits. DoctorAccrual consumes BillFinalised once per bill-line/rule version; reversal on future credit note is a separate declared workflow. IRP registration consumes a persisted immutable taxable invoice, records IRN/QR externally, and retries/reconciles by document identity. BillIssued message MSG-008 carries only an expiring patient-access URL, never raw bill attachments. Patient link requires mobile OTP. Notification recording is per recipient/channel/message identity and cannot fail finalization. Exact provider deduplication and IRP document-release semantics remain G-DELIVERY/G-DOCUMENT decisions.

## Held decisions

- **G-STACK** (implementation): Confirm the proposed package/runtime profile and resolve a compatible lockfile. The archived constitution says Laravel 12; the pinned starter declares Laravel 13.17+ and PHPUnit, not Pest.
- **G-COMMIT** (implementation): Accept or revise the proposed atomic completion boundary: number, bill, deposits, receivables, ledger, audit and outbox commit together. Doctor accrual and remote delivery are durable asynchronous reactions.
- **G-LATE** (implementation): Can further charges arrive after finalization? Choose one-final-per-encounter versus supplemental bills, and the close/reopen policy. Proposed: check and lock a charge-set revision; reject a stale request without consuming a number.
